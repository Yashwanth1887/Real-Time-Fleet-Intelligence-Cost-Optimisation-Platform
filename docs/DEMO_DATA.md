# Synthetic demo data

FleetGuard generates synthetic vehicle IDs in the `FG-#########` namespace. Telemetry locations are sampled inside a broad continental-US bounding box; they do not represent tracked drivers or real routes. Vehicle, trip, location, fuel, speed, and behavior signals are generated by `simulator/main.py` with a reproducible random seed in normal mode.

The idle scenario sends six events for one newly chosen synthetic vehicle, with timestamps spaced 30 simulated seconds apart. At the default 120-second threshold it should trigger one idle alert when the worker consumes the fifth event. It creates no claims about production vehicle volume: `--vehicle-count 100000` defines an ID pool only.

The idempotent demo seed creates a synthetic fleet-manager account from environment-provided credentials, eight deterministic synthetic vehicles, two synthetic driver labels, sample trips and daily summaries, two explainable example alerts, one idle cost event and recommendation, fleet metrics, and current live-state examples in MongoDB and Redis. These seed values are clearly synthetic fixtures and must not be presented as observed fleet results. No private or real vehicle data is used.
